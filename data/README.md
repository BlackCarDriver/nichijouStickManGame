# data/ 数据说明（人类 + AI Agent 编辑前必读）

所有游戏内容数据都在这里，**JSON 是唯一真源**：游戏、编辑器、校验脚本共用。

```
data/
├── materials.json        # 材质表（物理/破坏属性 + 子弹交互）
├── weapons.json          # 武器表（射速/伤害/弹速/弹药）
├── prefabs/*.json        # 预制件（多个形状+材质组成的可复用物体）
└── maps/*.json           # 地图
```

改完任何文件后，**先跑校验**：

```bash
npm run validate
```

> **物体文字**：任何地图物体/预制件部件都可以带 `label`（招牌、告示、按键提示），
> 纯视觉、不参与物理：`{ "label": { "text": "出口", "size": 22, "color": "#ffffff", "anchor": "top" } }`
> `anchor` 为九宫格位置（center/top/bottom/left/right/topLeft/topRight/bottomLeft/bottomRight）。

## 坐标与单位约定

- 原点在**左上角**，`y` 向下，单位 px。
- `rect`：`x,y` = **左上角**，`w,h` = 宽高。
- `circle`：`x,y` = **圆心**，`radius` = 半径。
- `polygon`：`x,y` = **中心**；`vertices` 是**相对中心**的顶点；或 `sides` + `radius` 表示正多边形。
- `angle`：角度制，**正值顺时针**，一律绕图形**中心/质心**旋转。
- 预制件实例的 `x,y` = 预制件**中心**（锚点）。

## 质量尺度（重要）

玩家火柴人的物理质量约 **6.9**（density 0.002 × 36×96）。因此：

| 材质 | density | 典型物体质量 | 手感 |
|------|---------|--------------|------|
| cardboard | 0.001 | 80×80 箱 ≈ 6.4 | 轻，玩家可推动 |
| wood | 0.002 | 300×16 板 ≈ 9.6 | 略重于玩家，可压动跷跷板 |
| metal | 0.008 | r30 球 ≈ 22.6 | 重，难推但会滚 |
| plank | 0.002 | 300×16 板 ≈ 9.6 | 同木头，但**不可破坏**（跷跷板/机械件专用） |

> `plank`（厚木板）存在的理由：跷跷板这类**会被反复撞击**的机械件如果用 `wood`，
> 撞击伤害会把板子打坏（重物压上去、端点砸地面都会掉耐久），玩一会儿跷跷板就没了。
> `destructible: false` 让它只负责物理行为、不参与破坏系统。

## 硬度（`hardness`）

伤害先按 `damageMultiplier` 缩放，**再减去硬度**（最低 0）：

```
实际伤害 = max(0, 伤害 × damageMultiplier - hardness)
```

- 若 `实际伤害 = 0` → 这次攻击**完全打不动**该物体（只冒一个火花，耐久不变）
- 投掷武器（匕首/长矛）若 `投掷伤害 - 硬度 <= 0` → **插不进去**，会掉在地上成为可拾取武器

当前材质硬度：

| 材质 | 硬度 | 效果示例 |
|------|------|----------|
| cardboard | 0 | 任何伤害都生效 |
| ice | 1 | 激光(4) → 3/跳 |
| wood | 3 | AK(9)→6、手枪(14)→11、激光(4)→1 |
| solid | 5 | AK→4、激光(4)→**0（打不动）** |
| metal | 20 | AK/手枪/霰弹/激光/拳/踢 **全部 0**；光刀 35、狙击 50；匕首投掷(18)**插不进会掉落**，长矛投掷(26)能插入 |
| wall / ground | 999 | 不可破坏（也插不进） |

### 投掷物能否钉进材质（`stickable`）

| 取值 | 含义 |
|------|------|
| `true` | **总能钉进去**（忽略硬度）—— 地面 `ground` 就是这种 |
| `false` | **永远钉不进去** —— 墙 `wall` |
| 不填 | 按"投掷伤害 > 硬度"判定（木头/金属等） |

为什么不复用耐受度/免伤：那两个是"抗伤害"，而"能不能钉进去"是**穿透**问题。
地面不可破坏（耐受度 0），但匕首显然应该能插在土里 —— 用同一个数值表达会互相干扰。
不填 `stickable` 时，钉入条件就是"投掷伤害 > 硬度"。

**新增材质时保持这个量级**：如果 density 取 1（旧值），物体质量会是玩家的几百倍，
玩家推不动、跷跷板也不会动。

### materials.json

```jsonc
{
  "version": 1,
  "materials": {
    "wood": {
      "name": "木头",                 // 显示名
      "color": "#8b5a2b",             // hex 颜色（不是数字！无贴图时的填充色）
      "texture": "textures/wood.png", // 可选：public 下相对路径，或 data: 内联图
      "textureMode": "tile",          // 可选：tile(平铺) | stretch(拉伸)，默认 tile

      // ---- 物理 ----
      "fixed": false,                 // 默认是否固定位置
      "density": 0.002,               // 密度（见下面的质量尺度）
      "friction": 0.4,                // 动摩擦 0~1
      "frictionStatic": 0.8,          // 静摩擦 0~1
      "bounce": 0.1,                  // 物理反弹系数 0~1

      // ---- 破坏 ----
      "destructible": true,           // 是否可被破坏
      "durability": 60,               // 耐受度（HP，0 = 不可破坏）
      "damageMultiplier": 1,          // 受伤倍率（>1 更脆）

      // ---- 子弹交互（M3 武器系统使用）----
      "bulletBounce": false,          // 子弹击中是否反弹（金属 = true）
      "bulletPierce": false,          // 子弹是否可穿透（纸箱 = true）

      // ---- 接触伤害（危险物：岩浆/尖刺/毒液池）----
      "damagePerSecond": 20,          // 火柴人贴着它时每秒掉多少血（0/不填 = 无伤害）

      // ---- 爆炸（不填 = 不炸）：被破坏时原地爆炸 ----
      "explosive": {
        "damage": 60,               // 中心伤害（按距离线性衰减到 0）
        "radius": 150,              // 范围 px
        "knockback": 14             // 击退强度（不填 = 按半径自动推算）
      },

      // ---- 发光（不填 = 不发光）----
      "glow": {
        "color": "#ff8800",           // 光晕颜色（不填 = 用材质自身颜色）
        "brightness": 1.2,            // 亮度 0~3（叠加混合，>1 更亮）
        "radius": 24,                 // 范围 px：光晕向外扩多远
        "mode": "pulse"               // 发光方式：constant 常亮 / pulse 呼吸 / flicker 闪烁
      }
    }
  }
}
```

### 接触伤害（`damagePerSecond`）

材质的物体**被火柴人贴着**时持续掉血，不是"撞一下掉一次"：

- 数值就是"每秒伤害"：`damagePerSecond: 20` → 站着不动每秒掉 20 点血（满血 100 → 5 秒）
- **触碰瞬间先结算一次**（否则要等下一个结算点，手感像"没反应"），之后按 0.25 秒一次结算
  （每次 `dps × 0.25`），与帧率无关；伤害先扣护盾
- 相位跟着"接触那一刻"走：先撞一下 → 立刻掉一次，再每 0.25s 掉一次；离开再碰 = 重新算一次
- 伤害数字每秒汇总弹一次（不会 4 次/秒刷屏），且**不触发**受击顿帧/震屏/受击姿势
- 联机：由"被烫的那个玩家自己"上报（`dmg` + `kind: env`），服务端权威扣血，
  房主/客户端看到的血量一致
- 触发条件是"持续接触"（Matter `collisionactive`）：站着、贴着、压在上面都会掉血，离开即停

参考值：岩浆 `30`、尖刺 `15`、电地板 `10`、毒液 `8`（按关卡难度调）。

### 发光（`glow`）

给材质加一层**外发光**（岩浆、霓虹、水晶、发光按钮）：

| 字段 | 说明 |
|------|------|
| `color` | 光晕颜色（hex）。不填 = 用材质自身的 `color` |
| `brightness` | 亮度 0~3，默认 1。叠加（ADD）混合，值越大越亮，>1 会过曝 |
| `radius` | 范围 px（1~400，默认 18）：光晕向外扩散多远 |
| `mode` | 发光方式：`constant` 常亮 / `pulse` 呼吸 / `flicker` 闪烁 |

实现：`src/map/MaterialGlow.ts` —— 在物体**背后**按形状画 10 层放大的同色叠加，
由内到外逐层降低不透明度形成柔和光晕（不需要后处理 bloom，Canvas 渲染器也能跑）。
支持矩形/圆形/多边形，焊接预制件的每个部件按自己的材质发光。

呼吸 / 闪烁是纯表现：相位由**物体 id** 派生（无随机数），所以联机两端表现一致、可复现。

### 爆炸（`explosive`）

物体**被破坏时**在原地爆炸（油桶、炸药箱、易爆气罐）：

| 字段 | 说明 |
|------|------|
| `damage` | 爆炸中心伤害，按距离线性衰减到 0 |
| `radius` | 爆炸范围 px（1~1200） |
| `knockback` | 击退强度（不填 = 按半径自动推算，约 `radius/10`） |

- **不产生弹片**（弹片是手榴弹/火箭筒专属，见 `weapons.json` 的 `explosion.shrapnel`）
- 同一个爆炸还会：推动范围内的动态刚体、按伤害破坏附近的物体
  → 因此**可以连锁爆炸**（每个物体最多爆一次，不会无限递归）
- 联机：破坏事件是广播的，所以光效与物体伤害各端一致；
  玩家伤害由**各自客户端为自身上报**（`kind: env`），服务端权威扣血
- 校验会提示：`damage: 0` 时只有推力不掉血

**多边形顶点约定（顶点编辑依赖）**

- `polygon` 的 `x,y` 是**旋转枢轴**；编辑器保存自定义顶点时会做一次**质心归一化**
  （顶点质心移到局部原点，`x,y` 相应平移），保证"世界顶点 = (x,y) + R(angle)·v"
- Matter 刚体**必须是凸多边形**：凹形状会被引擎内部取凸包。
  编辑器用**红色虚线**画出物理实际形状（凸包）作为提示
- 手写时优先给**凸**多边形；凹形请拆成多个凸多边形拼接

**贴图说明**

- 路径相对 `public/`：`"textures/wood.png"` → 运行时 `/textures/wood.png`
- 也可以写 `data:image/png;base64,...`（"内嵌到 JSON"，自包含但会撑大文件；>200KB 会有警告）
- **贴图只作用于矩形物体**；圆形/多边形仍用 `color` 纯色
- 贴图缺失时自动回退纯色，不会报错；`npm run validate` 会提示文件不存在
- 占位贴图可重新生成：`node tools/gen-textures.mjs`

**占位贴图**：`public/textures/{wood,metal,cardboard,ice,ground,wall}.png`（64×64，可平铺）

```jsonc
  "width": 2400, "height": 1200,

      "type": "rect",            // rect | circle | polygon
      "x": 0, "y": 1120, "w": 2400, "h": 80,

      "color": "#3d5a3d",        // 可选：颜色覆盖
      "label": {                 // 可选：物体上的文字（纯视觉，不参与物理）
        "text": "出口", "size": 22, "color": "#ffffff", "anchor": "top"
      }
    }
  ],
  "prefabs": [{ "id": "table_1", "ref": "table_wood", "x": 420, "y": 1080, "fixed": true }],
  "joints": [
    { "id": "seesaw_pivot", "type": "revolute", "bodyA": "seesaw_plank",
      "anchor": { "x": 2170, "y": 998 } },        // bodyB 省略 = 固定在世界锚点
    { "id": "chain_1_2", "type": "revolute", "bodyA": "chain_1", "bodyB": "chain_2",
      "anchor": { "x": 800, "y": 208 }, "noCollide": true }   // 两体相连 + 同组不互撞
  ],
  "weaponDropZones": [{ "x": 200, "y": 80, "w": 2000, "h": 100 }],   // 全局随机空投的 x 范围
  "items": [{ "type": "medkit", "x": 1200, "y": 1100 }],             // 固定补给点（医疗包/防弹衣）
  "weapons": [                                                       // 武器掉落点（补给站）
    { "x": 500, "y": 1120, "mode": "fixed", "weapon": "sniper",
      "respawnMs": 12000 },
    { "x": 900, "y": 1120, "mode": "random", "pool": ["pistol", "ak47"],
      "respawnMs": 8000, "maxRespawns": 3 }

```

### 关节（`joints[]`）

现在只有一种：`revolute`（销轴／铰链），**两端能绕锚点自由旋转**，可用来做跷跷板、
吊链、三节棍、可摆动的吊钩平台。底层是 Matter 的 0 长度约束（pin）。

| 字段 | 说明 |
|------|------|
| `type` | 只能是 `"revolute"`（自由旋转，暂时没有角度限位） |
| `bodyA` | 主体 id：地图物体 id / 预制件焊接体实例 id / 预制件松件部件 id（`instId#i`） |
| `bodyB` | 另一端 id；**省略或 `"world"` = 固定在世界锚点上**（像挂在天花板上） |
| `anchor` | 世界坐标铰链点，**必须落在两体的接缝上**（中心距 = 段长时正好是接缝中点） |
| `noCollide` | 默认 `false`。`true` = 这条关节串起来的刚体彼此**不碰撞**（同一负碰撞组） |

**`noCollide` 什么时候必须开**：链条/三节棍旋转时，相邻两段的端面会互相顶，求解器会被碰撞推开 →

关节缝被拉开（实测 30×30 粗段、端面完全贴合时缝在 **30px ↔ 43px** 之间抖，看上去像“伸缩”）。
开了 `noCollide` 后，同一串（含它俩吊着的东西）互不碰撞，但仍会正常撞玩家/地形。
分组按**连通分量**算：一个链节同时属于两条关节也没问题。

**打断吊链的条件（重要）**：关节本身没有耐久，
"被子弹打断"= 把这一节的物体打爆（材质 `destructible` + `durability`）——
销毁时会把引用该刚体的关节约束一并摘掉，剩下的部分继续挂在其它链上摆动。
所以链节材质选 **`chain`**（动态、耐久 24、`bulletPierce: false`）最合适：
AK 3 发 / 手枪 2 发 / 狙击 1 发打断，且子弹**不会穿透**去打第二条链；
用 `wood_2`、`cardboard_2` 会穿过去（它们是 `bulletPierce: true`），一枪能同时打断两条。

现成例子：`data/prefabs/hanging_platform.json`（吊链平台预制件）与 `data/maps/crane.json`（放两个实例，可试断链）。

### 物体文字（`label`）

任何地图物体 / 预制件部件都能带文字（招牌、路标、按键提示、告示）：

| 字段 | 说明 |
|------|------|
| `text` | 文案（支持 `\n` 换行） |
| `size` | 字号 px（4~400，默认 20） |
| `color` | 颜色（hex，默认 `#ffffff`） |
| `anchor` | 位置：`center`（默认）/ `top` / `bottom` / `left` / `right` / `topLeft` / `topRight` / `bottomLeft` / `bottomRight` |

- **纯视觉**：不参与物理/碰撞，随物体移动与旋转
- **层次跟着物体走**：文字的渲染色阶 = 所属物体的层次 + 0.5（压在自己物体之上）
  - `layer: "decor"` 的物体在 **-2**、它的文字在 **-1.5** → 都在火柴人（0）**之下**，不会挡住玩家
  - `layer: "solid"` 的物体在 **-1**、它的文字在 **-0.5** → 仍在玩家之下，但在 decor 之上
- 自动加黑色描边（按字号取粗细），压在任意贴图/材质上都读得清
- 编辑器：地图页选中物体、预制件页选中部件，右侧属性面板里直接改（文案清空 = 删除文字）

### 投放点（`weapons[]`）

地图上的"补给站"：开局在该点生成**一份内容**（武器，或医疗包/防弹衣），可配置被捡走后是否重新刷新。
（**预制件也能自带枪位**，见[预制件自带武器掉落点](#预制件自带武器掉落点weapons)。）

**默认原地生成**（`falling: false`）：武器就出现在你放的 `x,y` 上。
早期是"从 y-240 处落下"，但如果这个点放在屋檐/门框下面，武器会被顶挡住、停在屋顶上 ——
所以默认改成原地生成；想要"从天而降"的观感时给该点加 `"fromSky": true`。

| 字段 | 说明 |
|------|------|
| `x` / `y` | 生成坐标（默认直接在这一点生成；脚下 22px 内没有支撑时会自然落到地面） |
| `fromSky` | 是否从天而降（默认 `false`）。`true` = 从 `y-240` 处落下，上方有遮挡会停在遮挡物上 |
| `mode` | `fixed`（默认）= 固定内容；`random` = 从候选池随机 |
| `weapon` | `mode: fixed` 时的武器 id（旧字段 `type` 等价）；**写道具 id 也能用** |
| `item` | `mode: fixed` 时的道具 id（`medkit` / `armor`）。填了它就按补给点处理 |
| `pool` | `mode: random` 的候选 id 数组，**武器与道具可以混着写**；不填或空数组 = 全部武器 |
| `respawnMs` | 被捡走后多久重新刷新（ms）。**0 或不填 = 只刷一次，不刷新** |
| `maxRespawns` | 最多刷新几次。**不填 = 无限**；`0` = 不刷新 |

```jsonc
{ "x": 500, "y": 1120, "mode": "fixed", "weapon": "sniper", "respawnMs": 12000 }
// 无限刷新：每 12 秒补一把狙击枪

{ "x": 900, "y": 1120, "mode": "random", "pool": ["pistol", "ak47"],
  "respawnMs": 8000, "maxRespawns": 3 }
// 每 8 秒从手枪/AK 里随机补一把，最多补 3 次

{ "x": 900, "y": 1120, "type": "dagger" }
// 旧格式：等价于 mode:fixed, weapon:dagger，只刷一次

{ "x": 600, "y": 615, "mode": "fixed", "weapon": "ak47", "fromSky": true }
// 从天而降（会落在上方遮挡物上，一般用于露天平台）

{ "x": 800, "y": 1120, "item": "medkit", "respawnMs": 15000 }
// 医疗包补给点：原地生成，捡走后 15 秒再补

{ "x": 1100, "y": 1120, "mode": "random", "pool": ["ak47", "medkit", "armor"],
  "respawnMs": 12000 }
// 随机池里混着武器和道具：每次随机刷其中一种
```

实现：`src/world/WeaponSpawnerSystem.ts`。它给每个掉落点打一个 `tag`（`wspawn:N`），
靠"地上还有没有这个 tag 的武器"判断是否已被捡走，再按间隔/次数刷新。

### 全局自动空投（`autoDrop`，**默认关闭**）

**默认情况下地图不会有任何自动掉落的东西**：武器只能来自 `weapons[]` 投放点，
医疗包/防弹衣只能来自投放点（`item`）或固定点（`items[]`）。
需要"从天上随机掉、维持数量"的老玩法时，显式开启（**武器和补给一起生效**）：

```jsonc
"autoDrop": { "enabled": true, "count": 4, "intervalMs": 2800, "initial": 3 }
```

| 字段 | 默认 | 说明 |
|------|------|------|
| `enabled` | `false` | 不开启就完全不自动掉落 |
| `count` | 4 | 地图上维持的武器总数（只统计所有地面武器，含掉落点刷的） |
| `intervalMs` | 2800 | 多久检查一次并补投（补给的检查间隔也用它） |
| `initial` | 3 | 开局立刻投放几把武器 |

开启后，补给（`data/items.json` 里的 `maintain`）也会按同样的规则从天上补：
关掉时 `maintain` 完全不生效，药包/防弹衣只靠投放点与 `items[]` 固定点。

投放的 x 范围用 `weaponDropZones`（不填则用地图中间 60% 区域）。
编辑器"地图"Tab 的地图属性里有对应开关（关闭时显示说明，开启后才展开数值项）。

### 预制件内部关节（`joints[]`）

让一个预制件自带铰链（吊链、三节棍、可摆动吊平台），**放多少个实例关节都自动跟着走**。

| 字段 | 说明 |
|------|------|
| `bodyA` | `parts` 的**下标**（不是部件 id） |
| `bodyB` | 另一端 `parts` 下标；省略或 `"world"` = 固定在世界锚点 |
| `anchor` | 铰链点，**局部坐标**（相对预制件锚点 = 部件包围盒中心），实例化时自动旋转/平移 |
| `noCollide` | 默认 `false`；链条/三节棍必须 `true`，否则相邻段旋转时端面互顶、缝会被拉开 |

为什么用下标而不是部件 id：部件 id 是**实例级**生成的（`${实例id}#部件序号`），
写死 id 会让同一个预制件的两个实例撞 id（`buildMap` 会报"物体 id 重复"，联机销毁会串）。

注意：

- `bodyMode: "compound"` 时整件是一个刚体，内部关节无意义 → 校验器直接报错
- 部件**不要**写显式 `id`（同上，多个实例会撞 id；`npm run validate` 会直接报 error，编辑器载入/粘贴时会自动清掉）
- 链节叠放时"中心距 = 节长"，锚点就落在接缝上；材质用 `chain`（动态 + 不穿透子弹 + 耐久 24）
- 地图 Tab 里看不到预制件内部的关节（它们在预制件里编辑：预制件 Tab 右栏「内部关节」+ 画布粉色十字锚点）
- 画布交互：鼠标移到粉色十字 → 该关节高亮并露出 **蓝(A)/橙(B)** 两个端点，把端点拖到别的部件上就改连接；B 端拖到空白 = 改回 `world`；拖十字本身 = 移动铰链位置。连接中的两个部件会用对应颜色描边标出

现成例子：`data/prefabs/hanging_platform.json`（横梁 + 两条 3 节吊链 + 平台，8 个关节），
`data/maps/crane.json` 放了**两个实例**证明可复用：打坏其中一个实例的一条链，只会让那个实例的平台摆起来。

### 预制件自带武器掉落点（`weapons[]`）

想让"武器架 / 枪械台 / 补给箱"这种摆件**自带枪位**（放几个实例就有几个枪位）时用它。
字段与地图的 [`weapons[]`](#武器掉落点weapons) 完全一致，唯一区别是 **`x` / `y` 是预制件局部坐标**
（相对锚点 = 部件包围盒中心），实例化时按实例的位移/旋转/`flipX` 换算到世界坐标。

```jsonc
"weapons": [
  { "x": -55, "y": -56, "mode": "fixed", "weapon": "ak47", "respawnMs": 12000 },
  { "x": 55,  "y": -56, "mode": "fixed", "weapon": "sniper" },
  { "x": 0,   "y": -36, "mode": "random", "pool": ["pistol", "shotgun"], "maxRespawns": 3 }
]
```

- 不要写 `id`：展开时一律按 `${实例id}#w${序号}` 生成（写死会跨实例重复）
- 展开顺序固定为「先地图自带 `weapons[]`，再按 `prefabs[]` 顺序逐个实例」——
  **服务端会做同一份展开**（`server/gamedata.go`），所以联机模式下预制件里的枪位也会照常刷出来
- 编辑器：预制件页左栏「武器掉落点」区块 → `＋ 武器 / ＋ 随机` 添加，画布上直接拖动，右栏改属性

现成例子：`data/prefabs/weapon_rack.json`（武器架：3 个部件 + 2 把固定枪 + 1 个随机点），
`data/maps/crane.json` 里放了一个 `rack_1` 实例。

## 预制件的两种物理形态（bodyMode）

| 值 | 行为 | 适用 | 代价 |
|----|------|------|------|
| `loose` | 每个部件一个独立刚体 | 可逐块破坏；静态家具（`fixed: true`）也没问题 | 动态时整体受力可能散架/错位 |
| `compound` | 所有部件焊接成**一个复合刚体** | 桌子/箱子这类"一个整体"的物体：能被整体推动、踢飞、爆炸抛飞 | ① 物理属性只能取**面积最大部件**的材质 ② 整体掉耐久，无法逐块破坏 |

实现说明（`MapLoader.buildCompoundPrefab`）：

- 各部件先用 `Bodies.*` 建"离线刚体"，再用 `Body.create({ parts })` 合成复合体（Matter 会自动生成父体凸包）
- 视觉上是**一个 Container + 各部件为子对象**（本地坐标），每帧只把 Container 同步到刚体位置/角度
  → 不需要逐部件同步，性能与部件数量无关
- `inst.fixed` 优先级高于材质默认值；焊接体静态时同样会重新应用材质摩擦/反弹

## weapons.json（武器表）

```json
{
  "version": 1,
  "projectileGravity": 520,        // **全局唯一弹道重力**：所有子弹/投掷物共用一个加速度
  "weapons": {
    "pistol": {
      "name": "手枪",
      "attackMode": "shoot",          // shoot=逻辑弹道子弹 | beam=瞬时光束 | melee=刺击 | throw=投掷
      "automatic": false,               // true = 长按连射（AK47）；false = 点一次打一发
      "fireRate": 4,                   // 发/秒
      "damage": 14,                    // 单次命中伤害
      "knockback": 4.5,                // 命中玩家的击退强度
      "ammo": 12,                      // 弹药数；-1 = 无限（近战武器不消耗弹药）
      "bullet": {
        "kind": "dot",                 // 外观：dot | streak | rocket | grenade | thrown
        "speed": 1600,                 // **弹速 px/秒 —— 决定"子弹飞行时间"**
        // 子弹一般不写 gravity：统一用文件顶层 projectileGravity
        "range": 1500,                 // 最大飞行距离
        "size": 3,
        "color": "#ffe08a",
        "trail": 16,                   // 拖尾长度 px
        "maxBounces": 3,               // 最多反弹次数（材质需 bulletBounce=true 才反弹）
        "bounceDamageMul": 0.7,        // 每次反弹后伤害倍率
        "pierceDamageMul": 0.6,        // 每次穿透后伤害倍率
        "piercePlayers": false,        // 是否穿透玩家（激光类）
        "bounceAny": false,            // true = 对任意材质都弹跳（手榴弹落地）
        "bounceRestitution": 1         // 反弹速度保留系数（0.45 = 快速衰减）
      },
      "visual": { "style": "pistol", "length": 22, "thickness": 5, "color": "#2b2b36" }
    }
  }
}
```

### 关键约定

- **`bullet.speed` 是"子弹飞行时间"的唯一来源**：子弹不是瞬时的，
  按 `speed × dt` 每帧步进，所以同一段距离下速度不同 → 到达时间不同。
  手枪 1600px/s 飞 800px ≈ 0.5s；火箭炮 700px/s ≈ 1.14s。
- **重力是全局统一的**（`projectileGravity`，当前 520 px/s²）：
  所有子弹与投掷物共用同一个加速度，因此
  **下坠距离 = ½ · g · (距离 / 速度)²** —— 只由速度与距离决定。
  实测同距离 600px：手枪(1600) 下坠 40px，AK47(2000) 下坠 27px。
  想让整体弹道更弯/更平直，只改 `projectileGravity` 一个数；
  单个武器要特殊表现时才在 `bullet.gravity` 里覆盖。
- **弹速再快也不会穿墙**：每帧用「上帧位置 → 本帧位置」的射线求交，
  一帧跨多远都能检测到（不是只查当前点）。
- **穿透/反弹由"材质 + 武器"两边共同决定**：
  材质回答"会不会"（`bulletBounce` / `bulletPierce`），武器回答"几次、衰减多少"。
- `visual.length` 决定枪口位置（子弹起点 = 手部 + 该长度），
  改长度不用改代码，子弹起点会自动跟着走。
- `attackMode` 当前实现状态：`shoot` / `beam` 已可用；`melee` / `throw` 待 W3/W4。
- 火箭炮的 `explosion` 字段已预留，范围伤害在 W4 接入（当前只有直击伤害）。

### 抛壳（`casing`）

```json
"casing": { "length": 9, "width": 3.2, "color": "#d8b056", "speed": 5.4 }
```

- **纯视觉**，不建 Matter 刚体、不参与碰撞/联机同步：池化在 `src/fx/CasingSystem.ts`
  （同屏上限 90 枚，落地停留 0.9s 后淡出；机枪 12 发/秒也不会带来物理开销）
- **不填 = 该武器不抛壳**（激光 / 火箭 / 手榴弹 / 近战武器）
- 抛壳口在**机匣**（枪口往回收约 1/3 枪长），沿枪管上侧弹出 + 一点向后分速度，
  所以朝上/斜着打时抛壳方向会跟着枪身转，不会永远“向上飞”
- 落点高度由**出生时向下的一条射线**求出 → 落地一次小反弹后躺在原地
- `speed` 是 **px/帧**（16.7ms 一帧），越大飞得越远；`length/width` 是弹壳尺寸（px）
- **一枪一壳**：霰弹枪 7 颗弹丸也只抛 1 枚

当前配置：手枪 6.5×2.8 / AK 9×3.2 / 机枪 8.5×3.4 / 狙击 12×3.4 / 霰弹 9.5×5（红色壳）。

### 爆炸（`explosion`）

```json
"explosion": { "radius": 150, "damage": 60, "selfDamage": true, "knockback": 14 }
```

- `radius`：范围半径，边缘伤害线性衰减到 0
- 当前**火箭炮 115 / 手榴弹 125**（中心命中直接致死），爆炸半径 160 / 175
- `selfDamage`：**是否炸到投掷者自己**（火箭/手榴弹都是 true）
- 冲量按 `mass` 归一 → 纸箱和金属球获得相近的速度变化，不会出现"纸箱飞天/金属不动"

### 投掷（`throw`）

```json
"throw": { "speed": 640, "gravity": 1100, "range": 900, "fuseMs": 1500,
           "bounceAny": true, "bounceRestitution": 0.45 }
```

- 有 `fuseMs` → 引信弹：**撞到任何东西只弹开，不引爆**，到期才爆炸（手榴弹当前 **5000ms**）
- 有 `stickMs` → 投掷物插在目标上停留 N 毫秒后消失（匕首/长矛）
- `damage` 可覆盖主伤害（投掷伤害与刺击伤害不同）
- 近战武器投掷后**脱手**（武器不再回到手上）

### 动作与输入对应

| 输入 | 行为 |
|------|------|
| 主攻击（P1 左键 / P2 空格） | 开火 / 刺击 / 投掷手榴弹；全自动武器长按连射 |
| 副攻击（P1 右键 / P2 Shift、E） | 优先"替换地上武器"；否则踢（空手/枪械）或投掷（持匕首长矛） |
| 空格（P2 空格是攻击，不是跳） | P2 跳跃用 ↑ |

| G | **取出/收起手榴弹**（当前操作中的玩家） |

**武器获取**：出生空手，**所有武器只能靠捡**（天降武器 + 场上遗留的掉落物）。
空手时主攻击 = **出拳**（短距离、低伤害），副攻击 = 踢。**没有数字键切枪**。

### 手榴弹是背包道具（不是武器）

- 拾取手榴弹**不会替换手上的武器**，直接进背包（**上限 3 颗**，满了就留在地上）
- 按 **G** 取出 → 手上变成手榴弹 + **半透明抛物蚂蚁线**（弹道预览，遇障终止 + 落点十字标记）
- **左键投出**：初速固定（`throw.speed`），落点只由**方向**决定
- 投出后**自动切回上一个武器**（武器从未被卸下，只是被手榴弹临时盖住）
- 再按一次 G 可收起，不消耗
- 投出后死亡/复活会自动退出持握状态

### 掉落物行为

- **踢飞**：`KICK.knockback`(17) 水平击退 + `KICK.lift`(7) 上抛（≈腾空 27px）；
  对动态物体按 mass 归一施加 `objectImpulse`(14) + `objectLift`(4)
  · 上抛幅度对数值很敏感：lift 9→102px、7→27px、5→8px、3→3px（落地接触会吸收一部分）
- **每帧自动拾取**：空手靠近武器、或任何情况下靠近手榴弹，都会自动拾取（不需要按键）
- **落地**：用「上一帧位置 → 本帧位置」线段检测，并**提前 `REST_OFFSET`(18px) 判定落地**，
  所以不会出现"陷进地面一帧再弹回来"
- **支撑检测**：已落地的掉落物每帧检查脚下，平台被破坏后会重新开始下落
- **子弹外观**：锥形拖尾（沿**真实轨迹**渐细的多边形带，分外层辉光 + 亮核两层）
  + 三层发光弹头（外晕/本体/白热核心）。采样数按 `bullet.trail` 自适应（4~14 个），
  拖尾会跟着抛物线弯曲、反弹后也会折返，不是"当前方向反推的一条直线"
- **投掷物外观**：飞行中的匕首/长矛按武器本体长度绘制（`trail` = 武器长度），不是一个小点
- **插入停留**：钉在物体/地面上的匕首长矛停留 **10 秒**，最后 1 秒闪烁
- **射程 ≠ 抛物线**：投掷物 `throw.range` 是 3000（基本等于"飞到命中为止"），
  预览画的是抛物线，不会因为射程而在半路消失

### 近战动作（三段式：预备 → 出击 → 收势）

| 武器 | 动作 | 表现 |
|------|------|------|
| 匕首 / 长矛 | `thrust` 突刺 | 先反向蓄力后坐 → 弓步前冲（髋前压 13px、躯干前倾 22°、后腿蹬直）→ 缓慢归位 |
| 光刀 | `slash` 挥砍 | 抬刀蓄力 → 快速扫下（`slashOffset` -0.6→+0.75）→ 收势；双腿开立、躯干随挥砍扭转 |
| 空手 | `punch` 直拳 | 蹬地转腰送肩 → 前臂直出（沿准星）→ 收拳；后臂收紧护脸 |
| 踢 | `kick` | 前腿蹬出；**能把火柴人踢飞**（水平约 215px、腾空约 27px）或把可推物体踢飞 |

动作曲线用 `strikeCurve()`：负值=反向预备，1=打到底。不用 0→1→0 的正弦，
因为正弦没有"蓄力"和"急停"，读起来像慢悠悠地挥一下。

> 踩过的坑：`attackTimer` 只被赋值、忘了递减 → `attackProgress` 恒为 0，
> 所有攻击姿势分支都进不去（表现就是"近战完全没动作"）。

### 投掷物外观

飞行中**和插在目标上**的匕首/长矛都用**与手持完全相同的模型**渲染
（`drawHeldWeapon` 画到独立 Graphics，再按飞行方向旋转跟随），
不是画一根颜色相近的长条；插住后外观不变，只有消失前 1 秒才闪烁。

### 暴击（命中头部）

**命中头部 = 伤害 ×2**，判定在 `DamageSystem.damagePlayer()` 里统一处理，
所以子弹 / 激光 / 刺击 / 挥砍 / 出拳**自动全部支持**，不用各自实现。

- 头部区域：碰撞体中心上方 `headZoneOffset`(30px) 以内（碰撞体高 96 → 顶部 18px 带）
- 只对 `bullet` / `melee` 生效；**爆炸与摔落不暴击**（它们的 point 是爆炸中心/缺失）
- 挥砍：弧本身有 62°，几乎必然覆盖头部 → 会变成"永远暴击"；
  所以"砍到头"另用 **20° 窄窗口**，必须真的把刀扫到头部高度
- 表现：金色命中火花 + 伤害数字**加粗放大**（27px bold `#ff2d2d`，不用感叹号）

实测：手枪爆头 14→28、匕首爆头 22→44、光刀爆头 55→110（致死）、砍躯干不暴击

### 伤害气泡

受击时头顶冒出红色的 `-15`，上浮后淡出（`src/ui/DamageNumbers.ts`）。
**短时间内的连续伤害会合并**（320ms 窗口）：激光每秒 18 跳、霰弹 7 颗弹丸，
不合并会瞬间炸出一片小数字完全读不出来。

气泡显示的是**本次攻击的伤害值**，不是被剩余血量截断后的值：
血量只剩 1 时挨 100 伤害，气泡显示 `-100`（而不是 `-1`）。

### 受击闪白

按物体**真实多边形顶点**填充（不是 AABB）：倾斜的长方体、三角形都只有本体闪白。
实测倾斜矩形的闪白面积 4000 = 真实面积（旧 AABB 做法会是 9023）。

### 低矮物体可以踩上去

`Player.tryStepUp`：向前探一条竖线，若前方障碍顶面高出脚底 ≤ `stepHeight`(34px)
就直接抬上去 —— 地上的木板/薄板不会再把人卡住。高墙不会误爬
（竖直探测从墙体内部开始时会先打到墙下边缘，高度差≈0 被过滤）。

### 手感层（音效 / 顿帧 / 计分）

| 系统 | 说明 |
|------|------|
| `AudioSystem` | **程序化音效（WebAudio 合成，零音频文件）**：每把武器不同枪声、命中、爆炸、拾取、死亡、投掷、踢 |
| `HitStop` | 命中顿帧：冻结世界 22~70ms（时长按伤害量缩放），越重的打击越"实" |
| 受击镜头晃动 | trauma 0.12（约原来的 1/3，原 0.35 过晃） |
| 受击姿态 | 简化为"后仰护身"单帧姿势，时长 190ms（轻型伤害 80ms），不再四肢乱舞 |
| 击杀计数 | 击杀归属按伤害来源记录，HUD 显示 `P1 击杀 N` |

- 音效需要用户手势才能启动（浏览器自动播放策略），首次点击/按键时解锁
- **M 键静音**
- 顿帧是全屏双人共享的（同屏双人的取舍），时长刻意压得很短（≤70ms）

### 摔落伤害

- **玩家**：追踪空中最大下落速度，落地时 `伤害 = (速度 − 21) × 3.2`
  · 实测：150px 坠落（速度 13.6）不掉血；400px（22.3）掉 4.2；900px（31.9）掉 34.8
- **物品**：动态物体高速撞击时按速度掉耐久（`ImpactDamageSystem`）
  · `伤害 = min(45, (撞击速度 − 15) × 2.6)`，实测 200 耐久的木箱从高处落地掉 14
  · 只在**碰撞求解前**取速度（Matter 的 collisionstart 事件时机），求解后速度已归零

### 后坐力（`recoil`）

```json
"recoil": { "push": 9, "climbDeg": 2.2, "climbMaxDeg": 6, "recoverMs": 2600 }
```

| 字段 | 含义 |
|------|------|
| `push` | 开枪时把自己**沿瞄准反方向**推开的冲量（火箭 9 / 霰弹 7 / 狙击 6 / 手枪 1.2） |
| `climbDeg` | 每发让**枪口与弹道一起上抬**的角度（度）→ 需要玩家自己往下压枪 |
| `climbMaxDeg` | 上抬累计上限 |
| `recoverMs` | 从上限回落到 0 的时间。**必须比"射击间隔 ÷ climbDeg"慢**，否则连射时上抬累积不起来 |

关键点：上抬同时作用于**枪口绘制与子弹方向**，所以"看到枪口抬到哪，子弹就往哪飞"，
不会出现"视觉抖了但弹道没抖"的割裂感。

当前配置（实测）：

| 武器 | push | climbDeg | climbMax | recoverMs |
|------|------|----------|----------|-----------|
| 手枪 | 1.2 | 0.9 | 4.5 | 1400 |
| AK47 | 0.9 | 0.75 | 7 | 3000 |
| 机枪 | 0.65 | 0.55 | 9.5 | 3400 |
| 激光 | 0.15 | 0.1 | 4 | 4000 |
| 霰弹枪 | 7 | 2.0 | 8 | 2600 |
| 狙击枪 | 6 | 2.6 | 6 | 2800 |
| 火箭炮 | 9 | 2.2 | 6 | 2600 |
| 近战/投掷 | 0 | 0 | 0 | — |

`push >= 4` 时会额外触发轻微镜头震动（重武器手感更"重"）。

### 投掷预览（按住右键）

手持匕首/长矛时**按住副攻击键**（P1 右键 / P2 Shift）→ 显示抛物线预览（与真实投掷同一套模拟）；
**松开才投出**。快速点一下 = 立刻投出。

预览只画**前面一段**（`TrajectoryPreview.PREVIEW_LENGTH = 260px`）：
完整抛物线会把落点也画出来，投掷就没有"预判"的乐趣了。手榴弹的预览同样限制长度。

### 死亡表现

玩家死亡后：**倒地（450ms 转倒）→ 闪烁 2 秒（正常 ↔ 半透明）→ 消失（350ms）→ 复活**，全程约 2.8 秒。
插在目标上的匕首/长矛在**消失前 1 秒**也会闪烁。

### 武器外形风格（`visual.style`）

`pistol` / `rifle` / `laser` / `launcher` / `dagger` / `spear` / `grenade` / `lightsaber` / `mg`
—— 每种风格的轮廓画法在 `src/render/WeaponRenderer.ts`。
`lightsaber`（光刀）：**颜色跟随持有者**（红火柴人 → 红光刃，蓝火柴人 → 蓝光刃），
辉光色由本体色自动提亮推导。

**发光层用 ADD 混合**（`drawWeaponGlow` 画到独立的 ADD 混合 Graphics）：
普通 alpha 叠加只是"盖一层半透明"，越叠越灰；ADD 是颜色相加，才会真的变亮。
光晕四层 40px/16% → 26px/24% → 15px/42% → 8px/62% + 刀尖光团，
实测沿刃横向采样：0px 白热 → 4px `[225,155,167]` → 12px `[108,79,96]` → 20px 衰减到背景。

**挥砍留下扇形残影**（`SlashTrail`）：逐帧采样刀身实际扫过的角度，把相邻采样之间
扫出的楔形拼成扇形（越新越亮、越旧越淡），ADD 混合；挥砍结束后残影继续老化约 260ms 再消失。
不再是"连接起止角度的直线"。

### 霰弹（`pellets` / `spreadDeg`）

```json
"bullet": { ..., "pellets": 7, "spreadDeg": 16 }
```

- `pellets`：一次开火发射的弹丸数量（霰弹枪 7 颗）
- `spreadDeg`：散布**半角**（度），弹丸在 ±16° 内均匀分布 + 少量随机抖动
- 同一次开火的所有弹丸**共用一个 `attackId`** → 它们都能命中同一目标，
  不会被第一颗弹丸造成的受击无敌帧挡掉（否则 7 颗只会中 1 颗）
- 霰弹枪设计：7 颗 × 8 伤害 = 贴脸 56，射程只有 420px（近距离强、中远距离散开）

### 瞄准辅助线（`sight`）

```json
"sight": { "color": "#ff9b9b", "width": 1.6, "alpha": 0.45, "range": 3000 }
```

- 持有时**常驻显示**的半透明射线（狙击枪红外线），**纯视觉、零伤害**
- 逐帧重画（不是带寿命的特效），遇到障碍物终止在命中点 → 能直观看出"这一枪会不会被挡"
- 换枪 / 空手 / 死亡时立即消失

### 光束（`beam`）

```json
"beam": { "range": 2200, "width": 5, "color": "#7ef9ff", "duration": 90,
          "continuous": true, "tickMs": 55 }
```

| 字段 | 说明 |
|------|------|
| `continuous: true` | **连续光束**：按住攻击键持续输出，像机枪一样持续掉血（激光枪） |
| `tickMs` | 伤害间隔（毫秒）。当前 55ms ≈ 18 跳/秒，每跳 `damage`（4），DPS ≈ 67 |
| `pierce` | **是否贯穿目标，默认 false**（命中第一个目标就停）。激光当前为 false |
| 不填 `continuous` | 点一次打一发瞬时光束（一次结算全部沿途目标） |

连续模式的行为：

- **每 tick 扣 1 点弹药**（激光 45 发 ≈ 2.5 秒连续输出）
- 伤害**无视受击无敌帧**（否则 180ms 无敌会把绝大多数 tick 挡掉）
- 松开鼠标 / 换武器 / 死亡 → 立即停止输出
- 贯穿玩家；遇到不可穿透材质（墙/地面/金属）光束终止

### 近战动作（`melee.anim`）

| anim | 适用 | 判定方式 |
|------|------|----------|
| `stab`（默认） | 匕首、长矛 | 手部向前一条短射线，命中单体 |
| `slash` | 光刀 | **扇区判定**：角度差 ≤ arc + 目标半径，距离 ≤ reach，并做视线检查；一刀可扫多个目标 |

`arc` 是扇形**半角**（度）。光刀 62° = 左右各 62°。

### 弹药耗尽

弹药打空（或投掷出去 / **玩家死亡**）→ **武器直接消失**（不会掉在地上）。
**武器没有耐久度**，所以无限弹药的近战武器（匕首/长矛/光刀）在持有期间可以一直用，
但**一死就没了** —— 这也是近战武器的主要流转方式。武器补给完全依赖天降武器
（`DropSystem` 维持地图上 4 件，优先使用地图的 `weaponDropZones`）。

## 出生点规则（`npm run validate` 会检查）

- `lives` = 每人**可复活次数**：每次死亡扣 1，还有次数就 3 秒后满血、空手回到本队出生点
  （团队战回到本队半区，混战按出生点轮换）；计完即本局出局，团队战要全队命尽才判负。
- `spawnPoints` 的 `(x, y)` 是**玩家身体中心**（身体 36×96），所以站在地面上时
  `y = 地面顶部 - 48~49`。
- 出生点**不能落在任何实体物体内部**（箱子、木板、滑梯、跷跷板……），否则角色出生就被卡住，
  联机时表现为"按方向键不动"。校验器会报错：`出生点落在物体 xxx 内部，角色会被卡住`。
- 出生点也不能靠墙太近：左右留出至少一个身位（校验器按 ±19px 判断）。
- 多人乱斗建议 8 个出生点，并在高度/左右位置上分散，避免开局互相卡住。
